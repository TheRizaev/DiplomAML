# Экономически оптимальное выявление отмывания денег на графах транзакций

Код к выпускной квалификационной работе «Экономически оптимальное выявление отмывания денег на основе методов машинного обучения на графах банковских транзакций» (Филиал МГУ имени М. В. Ломоносова в г. Ташкенте, 2027).

*Budget-constrained, cost-optimal anti-money-laundering detection on transaction graphs: GNN / XGBoost risk scores, calibration, and selection of the top-K transfers by expected loss π̂·L on IBM AML HI-Small and LI-Small.*

## Идея

Аналитики банка могут проверить только `K` переводов в день. Цель — не поймать как можно больше отмывочных переводов, а **предотвратить как можно больший ущерб**. Метод:

1. строит граф счетов и переводов (протокол трёх графов: обучение / валидация / тест);
2. оценивает вероятность отмывания `p` графовой моделью (XGBoost на графовых признаках, графовая нейросеть для ориентированных мультиграфов, их гибрид и ансамбль);
3. калибрует вероятность (Платт или теоретическая поправка `logit π = logit p − log v`);
4. отбирает `K` переводов с наибольшим ожидаемым ущербом `π̂ · L`, где `L = min(A, C)` — потери при пропуске перевода суммы `A` с потолком `C = 10⁶ $`.

Качество измеряется долей предотвращённого ущерба `D_K`.

## Основные результаты

Тест, 3 запуска, отбор по `π̂ · L`, `L = min(A, 10⁶ $)`.

| | HI-Small: XGBoost | HI-Small: гибрид | HI-Small: ансамбль (калибр.) | LI-Small: XGBoost | LI-Small: гибрид |
|---|---|---|---|---|---|
| F1, % | 70,7 | 70,9 | 74,2 | 36,8 | 33,2 |
| Ущерб, K = 100, % | 57,0 | 65,5 | 65,9 | 30,9 | 49,4 |
| Ущерб, K = 1000, % | 79,7 | 84,5 | 85,1 | 76,4 | 66,5 |

При `K = 100` отбор по вероятности (стандартная очередь алертов) предотвращает лишь 2–5 % ущерба.

## Данные

Набор IBM Transactions for Anti Money Laundering (Altman et al., NeurIPS 2023):
<https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml>

Нужны файлы `HI-Small_Trans.csv` и `LI-Small_Trans.csv`. Скрипты ищут их в папке проекта, в подпапке `data/` или в папке «Загрузки» (`~/Downloads`).

## Порядок запуска

Скрипты запускаются по очереди из папки проекта. Каждый пишет результаты в `results_*.txt` и `metrics_*.json` рядом с собой.

```bash
python 05_check_env.py                      # проверка памяти, видеокарты и PyTorch
python 01_eda_heterophily.py                # анализ данных и гетерофилия
python 02_amount_tail.py                    # суммы, функции потерь, n_eff
python 04_xgb_protocol.py                   # XGBoost по протоколу трёх графов
python 09_ablation.py                       # абляция: что даёт граф
for s in 0 1 2; do
  python 07_gnn_seeds.py --loss class  --seed $s
  python 07_gnn_seeds.py --loss amount --seed $s
done
python 08_summary.py                        # сводка XGBoost и GNN
for s in 0 1 2; do python 10_hybrid.py --seed $s; done
python 11_summary.py                        # сводка гибрида и ансамблей
python 12_theory_checks.py                  # проверки главы 2
python 13_large_tx.py                       # ранжирование по диапазонам сумм
python 15_fig_data.py                       # данные для рисунков
python figures/charts.py && python figures/schemes.py
```

Второй набор данных включается переменной окружения `AML_DATA=LI-Small` (в PowerShell: `$env:AML_DATA="LI-Small"`); его результаты пишутся в подпапку `LI-Small/`. Долгое обучение гибрида: `python 10_hybrid.py --seed 0 --epochs 1500 --tag _long`, сводка по нему — `SUMMARY_TAG=_long python 11_summary.py`.

## Реализация графовой нейросети

Нейросеть написана на чистом PyTorch, без PyTorch Geometric/DGL, в духе Multi-GNN (Egressy et al., AAAI 2024): раздельные сети для входящих и исходящих сообщений, номера портов, обновление представлений рёбер, нормировка слоя с остаточной связью. Обучение идёт на всём графе за один шаг; для экономии памяти слои пересчитываются при обратном проходе (`torch.utils.checkpoint`).
